Dados de demonstração

Este conteúdo é o mesmo do README.md da entrega, que continua sendo a referência exigida pelo enunciado.

Como instalar e subir a aplicação está em Primeiros passos. Esta página descreve o que o seed cria e com quem entrar.

Carregar o seed 

npm run seed

Quem entrar como

Os seis usuários do seed cobrem os quatro papéis. Os ids são literais e aparecem em prisma/seed.ts, no scripts/verificar.sh e nas URLs — não são gerados.

O que o seed cria

Um comando (npm run seed) e a demonstração inteira está de pé: nada precisa ser cadastrado à mão. Todos os ids e todas as datas são literais, de modo que npm run db:reset seguido de npm run seed reproduz exatamente o mesmo estado — as capturas acima não envelhecem.

3 obras · 6 usuários · 4 fornecedores · 3 faixas em 2 obras · 8 pedidos.

A alçada

ObraFaixas
Residencial AuroraAté R$ 10.000,00 → Amanda · Acima de R$ 10.000,00 (faixa aberta) → Amanda → João
Galpão Logístico NorteAté R$ 5.000,00 → João — e nada acima disso
Reforma da SedeNenhuma faixa

As duas últimas linhas não são descuido. O Galpão não tem faixa aberta: um pedido acima de R$ 5.000,00 nessa obra não encontra regra, e é assim que o estado SEM_REGRA_APLICAVEL fica alcançável sem preparar nada. A Reforma da Sede é a outra ponta: obra sem alçada nenhuma, que é o estado vazio da tela 3.

Os dois últimos são a razão de o seed escrever o estado diretamente em vez de encená-lo pelas rotas: nenhuma sequência de chamadas produz “faixa editada depois de um pedido já ter sido submetido sob ela” sem um segundo passo manual. O que importa demonstrar é o estado — e ele é exatamente o que o ADR 0001 promete.

É o mesmo endereço, e a lista muda porque a vez é calculada no servidor a partir das etapas gravadas — não por um filtro da tela.

Resetar

npm run seed apaga o que havia e reescreve o mesmo estado — inclusive o pedido que o scripts/verificar.sh deixa ao provar a corrida. Para recriar o banco do zero, com as migrations:

npm run db:reset
